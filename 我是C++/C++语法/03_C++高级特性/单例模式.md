# 单例模式

单例模式（Singleton）是一个**创建型设计模式**，目标很明确：

> **保证一个类在整个程序中只有一个实例，并提供一个全局访问点。** 



## 基本概念

1. **单例模式的优点**

| 要求           | 备注                                                         |
| -------------- | ------------------------------------------------------------ |
| 全局唯一实例   | 单例模式确保一个类只有一个实例，防止在程序中创建多个实例可能导致的资源浪费或状态不一致问题。例如，数据库连接池、配置管理类等通常使用单例模式，以确保全局只有一个连接池或配置实例。 |
| 提供全局访问点 | 单例模式通过提供一个全局访问点，使得在程序的任何地方都可以方便地访问该实例。这对于那些需要在多个模块或组件之间共享的资源或服务尤为重要，如日志记录器、缓存管理器等。 |
| 延迟实例化     | 单例模式通常采用懒加载的方式，即在第一次需要使用实例时才创建。这有助于节省系统资源，特别是在实例创建成本较高或初期并不需要该实例的情况下。 |
| 避免命名冲突   | 通过将单例实例作为一个类的静态成员，可以避免在全局命名空间中引入多个实例，减少命名冲突的风险。 |
| 管理共享资源   | 在多线程环境下，单例模式可以有效管理共享资源，确保线程安全。例如，操作系统中的线程池、任务管理器等常使用单例模式，以协调多个线程对资源的访问。 |

---

2. **设计单例模式的考虑因素**

​	虽然单例模式有诸多优点，但在设计和使用时也需要注意以下几点：

- **线程安全**：在多线程环境下，需要确保单例实例的创建和访问是线程安全的，常用的方法有双重检查锁定（Double-Checked Locking）和使用静态内部类等。

- **延迟初始化**：根据需求选择是否采用延迟初始化，以平衡性能和资源利用。

- **可测试性**：单例模式可能会影响代码的可测试性，特别是在单元测试中，可能需要通过依赖注入等手段来替代单例实例。

- **限制扩展**：单例模式通过限制实例数量可能会限制类的扩展性，需谨慎使用。

---

3. **适用场景** 

- 需要确保全局只有一个实例的场景，如配置管理、日志系统、设备驱动等。

- 需要全局访问点来协调系统中的多个部分，如缓存、线程池等。

---

4. **不适用场景** 

- 需要多个实例以满足不同需求的场景。

- 对象的生命周期需要更灵活控制的场合。



## 各种单例模式

> 单例模式发展了很久，有多种写法

### 局部静态变量方式

懒汉式写法。最简单最好的方式，C++ 11以上 `static` 是线程安全的，推荐使用这种写法：简单且安全

```cpp
#include <iostream>
#include <mutex>
#include <memory>

class Singleton
{
public:
  static Singleton &getInstance()
  {
    static Singleton single; // 静态局部变量，全局只初始化一次，C++以上线程安全。懒汉式，代码执行到这里才初始化
    return single;
  }

private:
  ~Singleton()
  {
    std::cout << "Singleton instance destroyed." << std::endl;
  }
  Singleton() = default;                            // 私有构造函数，禁止外部实例化
  Singleton(const Singleton &) = delete;            // 禁止拷贝构造
  Singleton &operator=(const Singleton &) = delete; // 禁止赋值操作
};
```

```cpp
#include "singleton.h"

#include <iostream>
#include <thread>
#include <mutex>

int main()
{
  std::mutex mtx; // 互斥锁，保护输出操作

  std::cout << "Singleton1 instance address: " << &Singleton::getInstance() << std::endl;
  std::cout << "Singleton2 instance address: " << &Singleton::getInstance() << std::endl;

  std::thread t1([&]()
                 { std::scoped_lock lock(mtx) ;// 锁住互斥锁,可以看成是lock_guard的升级版，支持同时锁住多个互斥锁，防止死锁
                       std::cout<< "Thread 1 Singleton instance address: " << &Singleton::getInstance() << std::endl; });

  std::thread t2([&]()
                 { std::scoped_lock lock(mtx); // 锁住互斥锁，确保输出操作线程安全
                       std::cout<< "Thread 2 Singleton instance address: " << &Singleton::getInstance() << std::endl; });

  t1.join();
  t2.join();

  return 0;
}
```

---

```bash
Singleton1 instance address: 0x7ff64f7340b0
Singleton2 instance address: 0x7ff64f7340b0
Thread 2 Singleton instance address: 0x7ff64f7340b0
Thread 1 Singleton instance address: 0x7ff64f7340b0
Singleton instance destroyed.
```



### 饿汉式

饿汉式表示在程序启动就初始化。比 懒汉式安全，但是自动初始化会带来开销，比如程序执行完还没用到就浪费资源了

```cpp
class Singleton {
public:
    static Singleton& instance() {
        return instance_;  // 直接返回已创建对象
    }

    // 禁止拷贝和赋值
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

private:
    Singleton() = default;
    ~Singleton() = default;

private:
    static Singleton instance_;  // 类内声明
};

// 类外定义（程序启动时初始化）
Singleton Singleton::instance_;
```



### 懒汉式

懒汉式表示只有在使用时才初始化

使用静态成员变量指针方式的示例：线程不安全，加锁之后安全但更低效。**不推荐使用** 

```cpp
class SingletonLazy
{
private:
    SingletonLazy()
    {
    }
    SingletonLazy(const Single2Hungry &) = delete;
    SingletonLazy &operator=(const Single2Hungry &) = delete;
    
public:
    static SingletonLazy *GetInst()
    {
        if (single == nullptr)
        {
            single = new Single2Hungry();
        }
        return single;
    }
private:
    static Single2Hungry *single;
};
```

> 这种方式在多线程情况下不安全

---

加锁多线程安全，但是每次调用都加锁 → **性能差** 

```cpp
static Singleton* GetInst() 
{
    std::lock_guard<std::mutex> lock(mtx);
    if (instance_ == nullptr) {
        instance_ = new Singleton();
    }
    return instance_;
}
```



#### 双重检查锁（DCLP）

```cpp
static Singleton* GetInst() 
{
    if (instance_ == nullptr) 
    {
        std::lock_guard<std::mutex> lock(mtx);
        if (instance_ == nullptr) 
        {
            instance_ = new Singleton();
        }
    }
    return instance_;//检查不为空，已初始化，直接返回
}
```

---

1. 已初始化情况（快路径）

```cpp
if (instance_ != nullptr)
```

直接返回 **无锁 → 高性能**

------

2. 未初始化情况

多个线程同时进入：

```text
线程A → instance_ == nullptr → 进入加锁
线程B → instance_ == nullptr → 等锁
```

线程A加锁进入，为空创建对象：

```cpp
lock
if (instance_ == nullptr)
    new Singleton()
unlock
```

线程B拿到锁，但是已经创建了对象，不再创建：

```
拿到锁
if (instance_ != nullptr)
    不再创建
```

 **保证只创建一次**



**但是！** `new` 行为不是原子操作，上面的操作可能被 `CPU` 重排为下面的操作：

```bash
1️⃣ 分配内存
2️⃣ 调用构造函数
3️⃣ 把构造好的对象给到instance_
```

```bash
1️⃣ 分配内存
2️⃣ instance_ = 地址   ← 提前暴露
3️⃣ 构造对象
```

那么情况2 排队线程A 如果分配到空对象或还没构造完的对象，线程B 就会不为空直接返回对象，但是拿到了一个不完整的对象



#### 智能指针方式(懒汉式)

实现 **线程安全懒汉式单例（call_once 实现）** ，是基于上诉普通懒汉式的升级版本

```bash
线程A ─┐
        ├── call_once → 执行初始化
线程B ─┘                → 直接跳过
线程C ─────────────────→ 直接跳过
```

---

```cpp
#include <mutex>
#include <iostream>
#include <memory>

class SingletonOnceFlag{
public:
    static std::shared_ptr<SingletonOnceFlag> getInstance(){
        std::call_once(flag, []{
            _instance = std::shared_ptr<SingletonOnceFlag>(new SingletonOnceFlag());
        });
        return _instance;
    }

    void PrintAddress() {
        std::cout << _instance << std::endl;
    }
    ~SingletonOnceFlag() {
        std::cout << "this is singleton destruct" << std::endl;
    }
private:
    SingletonOnceFlag() = default;
    SingletonOnceFlag(const SingletonOnceFlag&) = delete;
    SingletonOnceFlag& operator=(const SingletonOnceFlag& st) = delete;
    
    static std::once_flag flag;
    static std::shared_ptr<SingletonOnceFlag> _instance;
};
```

在 `.cpp` 文件内声明：

```cpp
std::once_flag SingletonOnceFlag::flag;
std::shared_ptr<SingletonOnceFlag> SingletonOnceFlag::_instance = nullptr;
```



#### 辅助类智能指针方式

智能指针在构造的时候可以指定删除器，所以可以传递一个辅助类或者辅助函数帮助智能指针回收内存时调用我们指定的析构函数。

```cpp
#include <mutex>
#include <iostream>
#include <memory>

class SingleAutoSafe;
class SafeDeletor
{
public:
    void operator()(SingleAutoSafe *sf)
    {
        std::cout << "this is safe deleter operator()" << std::endl;
        delete sf;
    }
};

class SingleAutoSafe
{
public:
    static std::shared_ptr<SingleAutoSafe> getInstance(){
        static std::once_flag flag;
        std::call_once(flag, []{
            _instance = std::shared_ptr<SingleAutoSafe>(new SingleAutoSafe(), SafeDeletor());
        });
        return _instance;
    }

    void PrintAddress()
    {
        std::cout << _instance << std::endl;
    }
    //定义友元类，通过友元类调用该类析构函数
    friend class SafeDeletor;
    
private:
    SingleAutoSafe() = default;
    SingleAutoSafe(const SingleAutoSafe&) = delete;
    SingleAutoSafe& operator=(const SingleAutoSafe& st) = delete;
    ~SingleAutoSafe() 
    {
        std::cout << "this is singleton destruct" << std::endl;
    }
    static std::shared_ptr<SingleAutoSafe> _instance;
};
```

```cpp
#include "Singleton.h"

std::shared_ptr<SingleAutoSafe> SingleAutoSafe::_instance = nullptr;
```

但是这种单例，被智能指针共享了，声明周期可能被无限延长，**不再是强约束单例模式**



## CRTP奇异递归模板

**一种很重要的静态多态手段，基类模板以“派生类自身”作为模板参数，从而在编译期实现多态行为。** 

### 基本语法

```cpp
template <typename T>
class TempClass 
{
  //...  
};
//CRTP
class RealClass: public TempClass<RealClass>
{
  //...  
};
```



### 使用CRTP实现单例

```cpp
#include <memory>
#include <mutex>
#include <iostream>
using namespace std;

template <typename T>
class Singleton
{
protected:
    Singleton() = default;
    Singleton(const Singleton<T>&) = delete;
    Singleton& operator=(const Singleton<T>& st) = delete;

    static std::shared_ptr<T> _instance;
    
public:
    static std::shared_ptr<T> GetInstance()
    {
        static std::once_flag s_flag;
        std::call_once(s_flag, [&]() {
            _instance = shared_ptr<T>(new T);
        });

        return _instance;
    }
    
    void PrintAddress() 
    {
        std::cout << _instance.get() << endl;
    }
    ~Singleton() {
        std::cout << "this is singleton destruct" << std::endl;
    }
};

//cpp内
template <typename T>
std::shared_ptr<T> Singleton<T>::_instance = nullptr;
```

---

定义一个网络的单例类，继承上述模板类即可，并将构造和析构设置为私有，同时设置友元保证自己的析构和构造可以被友元类调用

```cpp
//通过继承方式实现网络模块单例
class SingleNet : public Singleton<SingleNet>
{
    friend class Singleton<SingleNet>;
    
private:
    SingleNet() = default;
    
public:
    ~SingleNet()
    {
        std::cout << "SingleNet destruct " << std::endl;
    }
};
```
