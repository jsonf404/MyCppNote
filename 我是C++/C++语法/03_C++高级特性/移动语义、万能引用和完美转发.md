# 移动语义、万能引用和完美转发

​		**为了避免不必要的拷贝，我们引入了移动语义；为了让模板函数在调用链中不丢失实参的值类别，我们引入了万能引用；再结合 `std::forward`，实现了完美转发，从而让移动语义在模板中得以正确发挥。** 



## 左值和右值

### 分类定义

| 分类        | 全称   | 是否有身份（identity） | 是否可取地址 | 生命周期       | 典型来源                         | 可否绑定到 `T&`       | 可否绑定到 `T&&`             |
| ----------- | ------ | ---------------------- | ------------ | -------------- | -------------------------------- | --------------------- | ---------------------------- |
| **lvalue**  | 左值   | ✅ 有                   | ✅ 可以       | 持久（可复用） | 变量名、函数返回引用             | ✅ 可以                | ❌ 不可以（除非 `std::move`） |
| **xvalue**  | 将亡值 | ✅ 有                   | ✅ 可以       | 即将被销毁     | **`std::move(x)`、返回右值引用** | ❌ 不可以              | ✅ 可以                       |
| **prvalue** | 纯右值 | ❌ 无                   | ❌ 不可以     | 临时对象       | 字面量、表达式结果               | ❌ 不可以（const除外） | ✅ 可以                       |
| **glvalue** | 泛左值 | ✅ 有                   | ✅ 可以       | ——             | lvalue + xvalue                  | ——                    | ——                           |
| **rvalue**  | 右值   | ❌或部分有              | ❌或部分有    | ——             | prvalue + xvalue                 | ——                    | ——                           |

---

```text
            expression
           /         \
     glvalue         rvalue
     /     \        /     \
lvalue   xvalue  prvalue  xvalue
```



### 类型判断

C++标准库提供了几个类型特性（头文件：`type_traits`）用于判断表达式的值类别：

- `std::is_lvalue_reference<T>`：判断类型`T`是否为左值引用

- `std::is_rvalue_reference<T>`：判断类型`T`是否为右值引用

- `std::is_lvalue<T>`（C++20起）：判断表达式是否为左值

- `std::is_rvalue<T>`（C++20起）：判断表达式是否为右值

```cpp
#include <iostream>
#include <type_traits>

void func(int& x)
{
    std::cout << "func(int&)" << std::endl;
}

void func(int&& x)
{
    std::cout << "func(int&&)" << std::endl;
}

int main()
{
    int a = 5;
    const int& ref = a;

    // 判断类型
    std::cout << std::boolalpha;
    // 使用 decltype((a)) 获取 a 的类型，包括引用
    // (a) 是一个左值表达式，所以 decltype((a)) 是 int&
    std::cout << "a 是左值: " << std::is_lvalue_reference<decltype((a))>::value << std::endl;
    std::cout << "ref 是左值引用: " << std::is_lvalue_reference<decltype(ref)>::value << std::endl;

    // 调用函数
    func(a);          // 调用func(int&)
    func(10);         // 调用func(int&&)

    return 0;
}
```

---

```cpp
a 是左值: true
ref 是左值引用: true
func(int&)
func(int&&)
```



## 万能引用

**作用：** 移动语义很好，但在写模板函数时，我们不知道用户会传进来一个左值还是右值。万能引用能自动感知传入参数的类型。

- 表现形式为 **`T&&`**，其中`T`是模板参数。

  ```cpp
  void check_reference(T&& x)
  ```

- 在特定条件下，编译器会将其解析为左值引用或右值引用。

- 能够统一处理左值和右值，适用于泛型编程中的参数传递。



### 引用折叠规则

万能引用之所以 “万能”，本质是**引用折叠（reference collapsing）**：

| 组合     | 结果  |
| -------- | ----- |
| `T& &`   | `T&`  |
| `T& &&`  | `T&`  |
| `T&& &`  | `T&`  |
| `T&& &&` | `T&&` |

> **“只要有一个 &，结果就是 &（左值优先）”** 

---



### T 推导规则

输出不同的实参去推导 `T` 的类型，`T` 的推导规则不同

| 输入                           | T 推导                             |
| ------------------------------ | ---------------------------------- |
| 左值 （`int a = 10`）          | 左值引用 （`int &`）               |
| 右值 （10）                    | 右值 （int）                       |
| 具名右值引用（`int&& c = 10`） | `c`是左值 - >  左值引用（`int &`） |

> - 为了支持完美转发，右值的 `T` 推导仍是右值(**没有引用**)。
>
> - 因为 `c` 有名字，`c` 类型是右值引用，但这个表达式本身是左值
>
>   > **具名的右值引用，是左值；匿名的右值引用，才是右值。** 



### 简单示例

```cpp
#include <type_traits>
#include <iostream>

template <typename T>
void check_reference(T &&x)
{
  std::cout << std::boolalpha;
  std::cout << "T is lvalue reference: " << std::is_lvalue_reference<T>::value << std::endl;
  std::cout << "T is rvalue reference: " << std::is_rvalue_reference<T>::value << std::endl;
  std::cout << "T is rvalue : " << std::is_rvalue_reference<T &&>::value << std::endl;
  std::cout << "x is lvalue reference: " << std::is_lvalue_reference<decltype(x)>::value << std::endl;
  std::cout << "x is rvalue reference: " << std::is_rvalue_reference<decltype(x)>::value << std::endl;
}

int main()
{
  int a = 10;
  check_reference(a);  // T被推导为 int&， 因此 T&& -> int& && -> int&
  check_reference(20); // T被推导为 int，  T&& -> int&&
    
  int &&c = 100;	//命名了的c会被当成左值使用
  check_referenc(c);	//c是表达式，是左值，T被推导为 int&
  check_reference(std::move(c));	//使用move就是右值了，T被推导为 int

  return 0;
}
```

输出：

```bash
T is lvalue reference: true
T is rvalue reference: false
T is rvalue : false
x is lvalue reference: true
x is rvalue reference: false

T is lvalue reference: false
T is rvalue reference: false
T is rvalue : true
x is lvalue reference: false
x is rvalue reference: true

T is lvalue reference: true
T is rvalue reference: false
T is rvalue : false
x is lvalue reference: true
x is rvalue reference: false

T is lvalue reference: false
T is rvalue reference: false
T is rvalue : true
x is lvalue reference: false
x is rvalue reference: true
```

> - 第三个例子中：实际中 `T` 被推导为 `int&`，这是因为 **命名的右值引用变量在表达式中被视为左值**。
> - 第四个例子中：使用 `move()` 得到的就是一个真正的右值了



## 完美转发

> **`T&&`（万能引用） + `std::forward`（条件转发） = 完美转发** 。完美转发使得模板也能正确使用移动语义

### 使用原因

由于：**具名的右值引用，是左值；匿名的右值引用，才是右值。** 

因此下例中 `arg` 永远是左值，原样转发就是为了解决这个问题而发明，可以根据输入值类别**原封不动**的给 `target` 

```cpp
void target(int& x)  { std::cout << "lvalue\n"; }
void target(int&& x) { std::cout << "rvalue\n"; }

template<typename T>
void wrapper(T&& arg)
{
    target(arg);   // ❌ 问题点
}
```

```cpp
int a = 10;
wrapper(a);        // 期望 lvalue
wrapper(20);       // ❌ 实际仍调用 lvalue 版本
```

> `arg` 是有名字的变量 ⇒ 永远是 lvalue 表达式



### 基本语法

使用 `std::forward` 

```cpp
#include <iostream>
#include <utility>  // 必须包含 forward

void target(int& x)  { std::cout << "lvalue\n"; }
void target(int&& x) { std::cout << "rvalue\n"; }

template<typename T>
void wrapper(T&& arg)
{
    target(std::forward<T>(arg));	// ✅ 完美转发：保留原始值类别
}

int main() {
    int a = 10;
    wrapper(a);   // 输出 lvalue ✔️
    wrapper(20);  // 输出 rvalue ✔️
}
```

> `T&&` 在模板中是**通用引用**，能接收左值和右值
>
> 但**接收后，有名字的 arg 一律变成左值**
>
> 必须用 `std::forward<T>(arg)` 才能**还原原本的左值 / 右值属性**



### 简单示例

```cpp
#include <iostream>
#include <type_traits>
#include <utility>

void process(int &x)
{
  std::cout << "Lvalue reference: " << x << std::endl;
}

void process(int &&x)
{
  std::cout << "Rvalue reference: " << x << std::endl;
}

template <typename T>
void wrapper(T &&argc)
{
  process(std::forward<T>(argc));
}

int main()
{
  int a = 10;
  wrapper(a); // 传递左值，调用 process(int &x)

  wrapper(20); // 传递右值，调用 process(int &&x)

  int &&c = 100;
  wrapper(c);            // c是一个左值，调用 process(int &x)
  wrapper(std::move(c)); // std::move(c)是一个右值，调用 process(int &&x)

  return 0;
}
```

---

```bash
Lvalue reference: 10
Rvalue reference: 20
Lvalue reference: 100
Rvalue reference: 100
```



如果不使用 `stdL::forward` ,就全是左值

```cpp
template <typename T>
void wrapper(T &&argc)
{
  process(argc);
}
```

```bash
Lvalue reference: 10
Lvalue reference: 20
Lvalue reference: 100
Lvalue reference: 100
```



### 泛型工厂函数示例

以下示例展示了如何使用原样转发实现一个泛型工厂函数，完美转发构造函数的参数，以高效创建对象

```cpp
#include <iostream>
#include <string>
#include <utility>

// 类的定义
class Person 
{
public:
    std::string name;
    int age;

    // 左值引用构造函数
    Person(const std::string& n, int a) : name(n), age(a)
    {
        std::cout << "Constructed Person(const std::string&, int)" << std::endl;
    }

    // 右值引用构造函数
    Person(std::string&& n, int a) : name(std::move(n)), age(a)
    {
        std::cout << "Constructed Person(std::string&&, int)" << std::endl;
    }
};

// 工厂函数，使用原样转发构造函数参数
template<typename T, typename... Args>
T create(Args&&... args) 
{
    return T(std::forward<Args>(args)...);
}

int main() {
    std::string name = "Alice";

    // 传递左值
    Person p1 = create<Person>(name, 30); 
    // 传递右值
    Person p2 = create<Person>(std::string("Bob"), 25); 

    return 0;
}
```



### 使模板使用移动语义

```cpp
#include <iostream>
#include <string>

// 类的定义
class BigObject 
{
public:
    std::string data;

    BigObject(const std::string& d) : data(d) 
    {
        std::cout << "BigObject constructed with lvalue" << std::endl;
    }

    BigObject(std::string&& d) : data(std::move(d)) 
    {
        std::cout << "BigObject constructed with rvalue" << std::endl;
    }
};

// 处理函数，左值和右值的重载
void process(const BigObject& obj) 
{
    std::cout << "Processing lvalue BigObject" << std::endl;
}

void process(BigObject&& obj)
{
    std::cout << "Processing rvalue BigObject" << std::endl;
}

// 包装函数，不使用原样转发
template<typename T>
void bad_wrapper(T&& obj)
{
    process(obj); // 始终以左值形式传递
}

// 包装函数，使用原样转发
template<typename T>
void good_wrapper(T&& obj) 
{
    process(std::forward<T>(obj)); // 原样转发
}

int main()
{
    std::string s = "Sample data";

    BigObject bo1 = BigObject(s);              // 使用lvalue构造
    BigObject bo2 = BigObject(std::move(s));   // 使用rvalue构造

    // 使用bad_wrapper
    bad_wrapper(bo1); // 始终作为左值处理
    bad_wrapper(BigObject("Temp")); // 作为左值处理，浪费移动语义

    // 使用good_wrapper
    good_wrapper(bo1); // 作为左值处理
    good_wrapper(BigObject("Temp")); // 作为右值处理，利用移动语义

    return 0;
}
```



## forward源码解析

`std::forward`之所以能进行原样转发，我们来看一下源码，`std::forward`实现了两个版本

### 返回左值引用版本

```cpp
template<typename _Tp>
    _GLIBCXX_NODISCARD
    constexpr _Tp&&
    forward(typename std::remove_reference<_Tp>::type& __t) noexcept
    { return static_cast<_Tp&&>(__t); }
```

---

**1.  `_GLIBCXX_NODISCARD`**

​		`_GLIBCXX_NODISCARD` 是一个宏，通常定义在 **libstdc++**（GNU的C++标准库实现）中，用于指示编译器不要忽略函数的返回值。具体来说，它通常被定义为 **C++17** 引入的 `[[nodiscard]]` 属性，或者对应的编译器特定属性。

- `[[nodiscard]]` **属性**：这是C++17引入的一个属性，用于标记函数的返回值不应该被忽略。如果调用该函数的返回值被忽略，编译器会发出警告。例如：

```cpp
[[nodiscard]] int compute() { return 42; }

void example() {
    compute(); // 编译器会发出警告，因为返回值被忽略
}
```

- **在**`_GLIBCXX_NODISCARD`**中的作用**：通过使用这个宏，`forward`函数的设计者告诉编译器和使用者：调用 `forward` 时，返回值不应该被忽略，因为它在转发参数时起到了关键作用。如果返回值被忽略，可能会导致意想不到的行为或性能问题。

---

**2.** `constexpr`

`constexpr` 是C++11引入的一个关键字，用于指示一个函数或变量可以在编译时求值。

- **在函数中的作用**：

- - **编译时计算**：`constexpr` 函数可以在编译时被求值，如果传入的参数也都是编译时常量。
  - **优化性能**：通过在编译时进行计算，可以减少运行时的开销，提高程序的性能。

- **在** `forward` **函数中的作用**：

- - **高效实现**：`forward` 是一个轻量级的操作，通常涉及简单的静态类型转换（如 `static_cast`）。将其定义为 `constexpr` 允许编译器在可能的情况下在编译时完成这些转换，从而避免不必要的运行时开销。
  - **支持常量表达式**：如果在编译时上下文中使用 `forward`，例如在 `constexpr` 函数中，它能够在编译时正确地转发参数。

---

**3.** `remove_reference`**作用**

```cpp
template<typename _Tp>
    struct remove_reference
    { using type = _Tp; };

  template<typename _Tp>
    struct remove_reference<_Tp&>
    { using type = _Tp; };

  template<typename _Tp>
    struct remove_reference<_Tp&&>
    { using type = _Tp; };
```

根据模板就近匹配规则，会按照最相似的方式进行匹配，优先匹配特例化版本，比如

`remove_reference<int>` 会调用第一个版本

`remove_reference<int&>`会调用第二个版本(特例化)

`remove_reference<int&&>`会调用第三个版本

所以我们对比这三个版本

```cpp
remove_reference<int>::type;
remove_reference<int&>::type;
remove_reference<int&&>::type;
```

这三个版本的type都为int，这样达到了去引用的效果。

所以带入typename std::remove_reference<_Tp>::type& __t

我们可以知道__t一定是个左值引用类型。



### 原样转发内幕

此时我们考虑对一个左值引用类型(int& )参数执行forward函数

```plain
template<typename _Tp>
    _GLIBCXX_NODISCARD
    constexpr _Tp&&
    forward(typename std::remove_reference<_Tp>::type& __t) noexcept
    { return static_cast<_Tp&&>(__t); }
```

**函数各部分解释**：

- **模板参数** `typename _Tp`： 定义了一个模板类型参数 `_Tp`，表示要转发的类型。
- `typename std::remove_reference<_Tp>::type& __t`： 使用 `std::remove_reference` 去除 `_Tp` 的引用性质，然后以左值引用的形式接受参数。
- `static_cast<_Tp&&>(__t)`： 通过 `static_cast` 将参数转换为 `_Tp` 类型的右值引用。这是实现完美转发的关键步骤，使得被转发的参数保留其原有的值类别。
- `noexcept`： 指明函数不会抛出异常，有助于编译器进行优化，并提高代码的异常安全性。

__t为int&类型，TP被实例化为int&, 通过引用折叠

int& std::forward<int&>(arg)

达到了原样转发的目的。

**模板参数** `typename _Tp`： 定义了一个模板类型参数 `_Tp`，表示要转发的类型。

同样我们分析右值引用类型原样转发原理



### 返回右值引用版本

```cpp
template<typename _Tp>
    _GLIBCXX_NODISCARD
    constexpr _Tp&&
    forward(typename std::remove_reference<_Tp>::type&& __t) noexcept
    {
      static_assert(!std::is_lvalue_reference<_Tp>::value,
      "std::forward must not be used to convert an rvalue to an lvalue");
      return static_cast<_Tp&&>(__t);
    }
```

这里限制了不能将右值引用转化为左值引用。

`__t`是右值引用类型，当我们执行： `int&& forward<int&&>(args)`

`_Tp`被实例化为`int&&`, 返回类型通过折叠变为`int&&` , 参数`__t`变为`int&&`类型



## move源码解析

`std::move`源码

```cpp
template<typename _Tp>
    _GLIBCXX_NODISCARD
    constexpr typename std::remove_reference<_Tp>::type&&
    move(_Tp&& __t) noexcept
    { return static_cast<typename std::remove_reference<_Tp>::type&&>(__t); }
```

可以看到move的实现很简单，无论`__t`是左值引用还是右值引用，都会通过

`static_cast<typename std::remove_reference<_Tp>::type&&>(__t)`

强制转换为去除引用的type, 再加上 `&&` 的类型，也就是具体的右值引用类型。
